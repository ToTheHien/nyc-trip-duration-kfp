# Requirements Sync Rule

Whenever you make or accept a change to requirements — whether by editing REQUIREMENTS.md directly, discussing a scope change, adding/removing features, or modifying acceptance criteria — you MUST:

1. Check each of the following files for consistency with the new requirements:
   - `PROJECT.md` — project goals, scope, constraints
   - `REQUIREMENTS.md` — functional and non-functional requirements
   - `ROADMAP.md` — phases, milestones, feature groupings
   - `STATE.md` — current status, completed work, next steps

2. Update any file whose content is now inconsistent or outdated due to the requirements change.

3. Keep updates minimal and surgical — only change what the requirements delta necessitates.

Do this before reporting the task as complete.
