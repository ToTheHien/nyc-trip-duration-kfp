<objective>
Make the quality gates enforceable from two places at once — the developer's commit and the CI run — and make the thin-component/fat-lib architectural rule a mechanical gate rather than a convention.

Purpose: REQ-A5 asks that `pre-commit` and CI reach the same pass/fail verdict on the same commit. Guaranteeing that rather than hoping for it takes two things: a single shared entrypoint both callers invoke, and a hook for every check stage CI runs — including the test stage, which the developer has explicitly approved adding on top of D-03's hygiene scope. REQ-A6 asks that the `lib/`-holds-all-pandas-logic rule be grep-verifiable; research (PITFALLS Pitfall 8) records that this rule is invisible until someone tries to unit-test a component and cannot, so it must be enforced before Phase 3 writes the first real component.

Output: `scripts/qa.sh`, `scripts/check_component_boundary.sh`, a five-hook `.pre-commit-config.yaml` covering every CI check subcommand, a CI workflow refactored onto the shared entrypoint, and a README documenting the contract.
</objective>

<environment>
Per CLAUDE.MD, all local Python/uv/pytest/ruff/mypy work uses the venv at `path/to/venv` with `UV_PROJECT_ENVIRONMENT=path/to/venv`. CI does not have that venv. `scripts/qa.sh` exists precisely to reconcile the two: it exports the variable only when not running under CI, so the same script text is correct in both places.

`path/to/venv` as written in CLAUDE.MD is repository-root-relative. `scripts/qa.sh` is invoked by pre-commit, by CI, and by a developer who may be sitting in any subdirectory, so the script MUST resolve that path from its own location rather than from `$PWD` — otherwise a call from `lib/` silently targets a nonexistent `lib/path/to/venv` and uv creates a brand-new environment there, breaking both the CLAUDE.MD mandate and the REQ-A5 parity guarantee.

EXTRA-DEV RULE (inherited from plan 01-01, binds every `uv` invocation in this plan). Always `uv run --extra dev <tool>`, never a bare `uv run <tool>`: `uv run` implicitly syncs the DEFAULT dependency set before executing, and `dev` is an optional extra, so a bare call uninstalls ruff/mypy/pytest as a side effect of running them. Under CI, where the workflow has already run `uv sync --frozen --extra dev`, add `--frozen` as well so the runner cannot mutate the lockfile.

Write `scripts/qa.sh`, executable (`chmod +x`), starting `#!/usr/bin/env bash` and `set -uo pipefail` (NOT `set -e` — several checks below inspect a non-zero grep exit deliberately).

Its first act is to locate itself, not to trust the caller's working directory: derive `REPO_ROOT` as the parent of the directory holding the script (`cd -- "$(dirname -- "${BASH_SOURCE[0]}")/.." && pwd`) and `cd "$REPO_ROOT"` before running anything. Every path the script then uses — the venv, the ruff `.` scope, the mypy `lib` scope, the pytest `testpaths` — resolves against the repository root regardless of whether the caller was in the root, in `lib/`, or in `components/ingest/`. Without this, `UV_PROJECT_ENVIRONMENT=path/to/venv` is a relative path interpreted against `$PWD`, so a call from a subdirectory points uv at a path that does not exist, uv silently creates a fresh environment there, and the script's verdict stops meaning anything.

Its second act reconciles the CLAUDE.MD venv mandate with CI: when the `CI` environment variable is unset or empty, export `UV_PROJECT_ENVIRONMENT="$REPO_ROOT/path/to/venv"` so every local invocation targets the mandated interpreter; when `CI` is set, leave it unset so the runner's own uv-managed environment is used. This single conditional is what lets the identical script text be correct on the developer's laptop and on the GitHub runner, which is what makes REQ-A5 parity structural instead of aspirational.

Its third act builds the uv invocation prefix once, so no subcommand can forget it: `UV_RUN=(uv run --extra dev)` locally, and `UV_RUN=(uv run --frozen --extra dev)` when `CI` is set. The `--extra dev` is load-bearing — `uv run` implicitly syncs the default dependency set first, so a bare `uv run ruff check .` uninstalls ruff, mypy and pytest from `path/to/venv` in the act of running ruff, and the developer's next invocation fails on a missing tool. The `--frozen` in CI additionally forbids lockfile mutation on the runner.

Then dispatch on `$1` with a `case`, exiting 2 with a usage message on an unknown subcommand, expanding `"${UV_RUN[@]}"` in each branch:
  - `lint`      -> `"${UV_RUN[@]}" ruff check .`
  - `format`    -> `"${UV_RUN[@]}" ruff format --check .`
  - `typecheck` -> `"${UV_RUN[@]}" mypy --strict lib`
  - `test`      -> `"${UV_RUN[@]}" pytest`
  - `boundary`  -> delegate to `"$REPO_ROOT/scripts/check_component_boundary.sh"`
The five tool argument lists must match what `ci.yml` runs today, byte for byte — they are being lifted out of the workflow, not redesigned. Preserve the D-02 mypy scope (`lib` only).

Write `scripts/check_component_boundary.sh`, executable, same shebang and `set -uo pipefail`. It resolves `REPO_ROOT` from `${BASH_SOURCE[0]}` and `cd`s there exactly as `qa.sh` does — it is invoked both through `qa.sh boundary` and directly (the fail-first proofs below call it directly), so it cannot assume the caller's working directory either. It then implements REQ-A6 as a real gate:

  Step 1 — collect the scan set. Use `git ls-files -- 'components/*.py' 'components/**/*.py'` so only tracked files are considered (an untracked scratch file must not be able to fail CI, and a deleted file must not linger).

  Step 2 — the non-vacuous guard, which runs BEFORE any pattern check. If the collected list is empty, print a message naming the scanned path and exit 1. A gate whose scan target has been renamed, emptied, or misspelled must fail loudly; silently reporting success is the exact failure mode this gate exists to prevent, and it is the difference between a real constraint and decoration.

  Step 3 — three violation checks, each a `grep -nE` over the collected files, each printing the offending file:line before failing. Collect all violations and exit 1 once at the end so a developer sees every problem in one run, not one per run.
    (a) Data-library imports: an import statement whose module is pandas or numpy, anchored to the start of a line allowing leading whitespace, and matching the plain-import, dotted-submodule, and from-import forms.
    (b) DataFrame-shaped method calls: a method call from the set groupby, merge, pivot, resample, apply, assign, astype, read_parquet, to_parquet, read_csv, to_csv. These are the operations research (ARCHITECTURE.md Pattern 1) says must live behind a single `lib` call.
    (c) Runtime dependency installation inside a component: the `packages_to_install` KFP decorator argument. Research (PITFALLS line 174, FEATURES line 32) records this as explicitly forbidden for this project — component dependencies come from the CI-built image, never from a pip install at pod start. Catching it now means Phase 3's REQ-B3 is already enforced when the first real component is written.

  Step 4 — exit 0 with a one-line confirmation naming how many modules were scanned, so a passing run is visibly non-vacuous.

The gate script lives under `scripts/`, deliberately outside `components/`, so its own pattern strings are never inside its own scan set and it cannot fail on itself.

Write `.pre-commit-config.yaml` using `repo: local` hooks ONLY. Do not reference `astral-sh/ruff-pre-commit`, `pre-commit/mirrors-mypy`, or `pre-commit/pre-commit-hooks`. Two reasons, both load-bearing: a mirror repo pins its own tool version independently of `uv.lock`, so the pre-commit verdict would silently drift from the CI verdict and break the REQ-A5 parity criterion; and a mirror repo is third-party code fetched and executed on every developer commit, an entire supply-chain surface that `repo: local` removes.

Declare exactly five hooks, in this order — matching the CI stage order so a failure surfaces at the same stage locally as in CI:
  1. `id: ruff-check`   -> `entry: scripts/qa.sh lint`,      `language: system`, `pass_filenames: false`, `files: \.py$`
  2. `id: ruff-format`  -> `entry: scripts/qa.sh format`,    `language: system`, `pass_filenames: false`, `files: \.py$`
  3. `id: mypy-strict`  -> `entry: scripts/qa.sh typecheck`, `language: system`, `pass_filenames: false`, `files: ^lib/.*\.py$`
  4. `id: boundary`     -> `entry: scripts/qa.sh boundary`,  `language: system`, `pass_filenames: false`, `always_run: true`
  5. `id: pytest`       -> `entry: scripts/qa.sh test`,      `language: system`, `pass_filenames: false`, `files: \.py$`

Hook 5 is the requirement-closing hook, added per D-03a on an explicit developer ruling. REQ-A5's acceptance criterion is "`pre-commit run --all-files` matches CI pass/fail on the same commit" — a pass/fail MATCH, which a hook set covering only lint and typecheck cannot deliver, because a commit whose sole defect is a behavioural regression passes pre-commit and fails CI. D-03 ("`ruff` + `mypy --strict` on `lib/`, nothing more") scopes the HYGIENE hooks — its stated rationale is minimising setup friction by excluding trailing-whitespace, YAML/TOML validation and similar noise — and D-03a records the developer's ruling that the test hook is an approved addition on top of that scope, not a violation of it. Both decisions now live in `01-CONTEXT.md`, so this is settled in the locked-decision artifact itself and not only in this plan's framing: run the tests, do not document a divergence. Cost is negligible — the `lib/` suite is a handful of pure-function assertions and runs in well under a second.

`pass_filenames: false` is required because each script runs the tool over its own configured scope (`.` for ruff, `lib` for mypy, `testpaths` for pytest) exactly as CI does; letting pre-commit append staged filenames would change the scope and reintroduce the drift this design exists to eliminate. The `files:` scope on hooks 3 and 5 is what produces the correct empty-input behaviour: a commit touching no matching file leaves the hook with zero matches, and pre-commit reports it Skipped rather than Failed. Hook 4 is `always_run` because a deletion under `components/` must still be able to trip the non-vacuous guard even though no file matches a content filter.

Beyond these five, D-03's hygiene scope holds: no trailing-whitespace, end-of-file-fixer, YAML/TOML validator, or any other hygiene hook. All five hooks are read-only with respect to TRACKED files — ruff's checker in report mode, ruff's formatter in check mode, mypy, a grep gate, and pytest — so an interrupted or concurrent hook run cannot leave the developer's tree modified. The only files pytest writes are `.coverage` and `.pytest_cache/`, both gitignored by plan 01-01; confirm both entries are present in `.gitignore` before wiring the hook, because an untracked-but-unignored coverage file would make the read-only proof below fail for a spurious reason.
